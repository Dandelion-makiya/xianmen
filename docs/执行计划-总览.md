# 《仙门问道》开发执行计划总览

> 版本：1.0  
> 日期：2026-08-17  
> 目标：2026-08-17 ~ 2026-09-13（4 周）完成可运行的 Steam MVP

## 1. 总体目标

- 交付一个可完整通关的《仙门问道》Windows MVP。
- 技术栈：Unity 2022 LTS + C#，数据用 JSON 驱动。
- 内容范围：60 张卡、16 种敌人、15 个遗物、3 个奇遇、20 节点线性地图、单角色、单结局。
- 美术策略：前三周全部使用占位素材，最后一周统一替换像素国风素材。

## 2. 四个开发周期

| 周期 | 时间 | 主题 | 交付物 |
|------|------|------|--------|
| C1 | 8/17 – 8/23 | 项目框架 + 数据层 + 战斗核心 | 可完整打牌、跑完敌人意图的战斗 Demo |
| C2 | 8/24 – 8/30 | 完整游戏循环 | 地图 → 战斗 → 掉落 → Hub → 下一节点 全流程可玩 |
| C3 | 8/31 – 9/6 | 内容完善 + UI + 文案 + 平衡 | 全部剧情文案、5 大界面、首轮平衡版本 |
| C4 | 9/7 – 9/13 | 美术音效 + 测试 + 发布 | 可导出运行的 Windows 版本与发布准备 |

## 3. 周期验收标准

### C1 验收

- Unity 项目可在 Unity 2022 中直接运行。
- 60 张卡全部录入 JSON，效果原语全部可用。
- 16 种敌人的意图循环全部可执行。
- 回合流程、状态效果、伤害结算符合玩法文档。

### C2 验收

- 20 节点地图按规则生成，普通/精英/事件/打坐/Boss 分布正确。
- 战斗胜利掉落资源与卡牌，回 Hub 可买卡、祭炼、打坐、领取遗物。
- 3 个奇遇事件可触发并即时结算。
- 退出后可从 Hub 继续当前局。

### C3 验收

- 主界面、战斗、Hub、地图、结算 5 个界面完整。
- 卡牌 flavor、遗物 flavor、敌人 lore、事件文本、结局文本全部植入。
- 数值按文档填写完毕，并完成至少一轮完整通关测试。

### C4 验收

- 美术资源统一替换，无占位色块遗留。
- 基础音效/音乐接入（如确认加入音频范围）。
- Windows 导出包可运行，主流程无阻断 Bug。
- 商店页素材与发布信息准备好。

## 4. 开发原则

1. 玩法文档是唯一数值事实来源，故事文档只提供展示文案。
2. 不在 MVP 范围内自行扩展系统；所有新增需求先修改策划文档。
3. 代码标识符全部使用英文，展示文本使用中文。
4. 数据与逻辑分离，卡牌、敌人、遗物、事件全部数据驱动。
5. 遵守 `.clinerules`：项目目录不产生、不残留 `.tmp` 文件。

## 5. 前置工作

在 C1 开始前，必须先确认《策划文档建议清单》中的 P0 项，并把结论同步回两份策划文档。未确认的数值或规则不得提前录入代码。
